Privacy

Your report leaves the Mac only when you press Send, and the Send screen lists what goes. Before that, the network tests move test data and nothing else.

TL;DR

  • Nothing about your Mac leaves it until you press Send.
  • Never sent: serial numbers, network addresses, Wi-Fi names, pictures, recordings, or anything from your disks.
  • Before you send: only random test data to boot.watch, and one check for the newest Mac list.
  • Once sent and accepted, your results and your Mac's hardware details are public on {{DIO}}, which doesn't record your IP address.
  • A bug report goes to OmaBoot? only when you send it. It's scrubbed first, stays private, is read by OmaBoot?'s maintainers and an AI model, and is deleted after 180 days.
  • This website: no cookies, no analytics.

What a report contains

  • Which Mac it is: the model identifier, Apple board ID, processor, the PCI and USB device IDs with the driver each one uses, memory size, firmware version, chassis type and kernel version.
  • The results: each test's outcome, how it was measured, and a short line of evidence, such as the Wi-Fi chip and how many networks a scan found. Devices you plug in for a port test can be named there by their model.
  • The run: the OmaBoot? Live version and image, any OmaBoot? fixes that took effect, and when the test ran.
  • A name to credit, only if you type one.
  • The notice from the Send screen, word for word, as the record of what you agreed to send.

What it never contains

Serial numbers, network (MAC) addresses, the computer's name, Wi-Fi network names or passwords, the names of nearby Bluetooth devices, camera pictures or microphone recordings, or any file or data from your disks.

Network traffic before you send

  • boot.watch, for the Wi-Fi and Ethernet tests and the sign-in page check: random test data, made from a seed the Mac picks, sent there and back so every byte can be checked. It carries nothing about your Mac. boot.watch keeps no request log and stores no addresses; it only counts tests and bytes. Its uptime is public at status.boot.watch, and how it works is in Docs.
  • {{DIO}}, once, for the newest list of Mac configurations, so OmaBoot? Live can tell yours apart. It sends only the version of the list it already has.

Offline, both are skipped: the tester uses the list built into the stick, and the network tests say they weren't tested.

When you send it

The report goes over HTTPS to {{DIO}}. A person reviews it before it counts toward a verdict or appears on the site.

Once a maintainer accepts it, its results, your Mac's hardware details and the name to credit, if you gave one, are public on {{DIO}}. The full report may be published later, once {{DIO}} has removed anything personal it finds in it. {{DIO}} doesn't record the sender's IP address. More in its privacy policy.

A report you save instead stays on the stick until you delete it.

Bug reports

A bug report is for when something goes wrong: the run's logs, its report, the screen as text, the boot messages, the network tests' log and, after a sleep test, its kernel lines. The console's bugreport saves one to the stick. It goes to OmaBoot? only when you type bugreport send, or when a run plan you wrote says send: true. It never goes to {{DIO}}.

  • Scrubbed before it leaves: serial numbers, network (MAC) and IP addresses, the computer's name, user names and e-mail addresses are removed on the Mac, and again when it arrives, with the same rules {{DIO}} uses for reports. The copy on the stick stays whole, so look before you share that one.
  • What else goes with it: the OmaBoot? Live version, the Mac's model and configuration, and your report's code if you sent the report. To limit how many a Mac can send in a day, the Mac also sends a one-way hash of its firmware's ID; boot.watch keeps that in memory until the end of the day and never stores it.
  • Where it goes: to boot.watch, which passes it on to a private storage bucket (Cloudflare R2) and keeps nothing of it. The bucket deletes it after 180 days. It is never published.
  • Who reads it: OmaBoot?'s maintainers, and an AI model (Anthropic's Claude) that looks through bug reports for problems many Macs share.
  • Its code: once it's sent, the console shows a code like B-7K2Q-9MXD. Quote it when you tell us about the problem, and we can find your report.
  • Offline, it waits on the stick, and the console offers to send it from the next run that's online.

This website

No cookies, no analytics, no third-party scripts or fonts. It's served by Cloudflare Pages, and the downloads by Cloudflare R2. Cloudflare handles each request, your IP address included, under its privacy policy; we haven't turned on any of its analytics, and nothing on the site sets a cookie.
